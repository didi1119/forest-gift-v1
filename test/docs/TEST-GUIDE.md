# 測試使用指南

## 📖 快速開始

### 1. 開啟測試執行器

在瀏覽器中打開：
```
test/TEST-SUITE.html
```

### 2. 配置測試參數

在測試控制台中設置：

- **Apps Script URL**: 您的 Google Apps Script 部署網址
- **測試大使代碼**: 用於測試的大使代碼（建議使用 `TEST_AUTO`）
- **測試類別**: 勾選要執行的測試類別
- **測試後清理數據**: 建議勾選（會自動刪除測試數據）
- **顯示詳細日誌**: 建議勾選（可查看詳細執行過程）

### 3. 執行測試

點擊「開始測試」按鈕，系統會：

1. 檢查測試大使是否存在（不存在會自動創建）
2. 按順序執行所選的測試
3. 顯示即時進度和日誌
4. 生成測試報告

### 4. 查看結果

測試完成後可以：

- 查看通過/失敗/跳過的測試數量
- 點擊各個測試查看詳細結果
- 導出 JSON 格式的完整報告

## 🔍 測試分類說明

### 基礎功能測試 (basic)

**執行時機**: 每次測試
**測試內容**:
- API 連線是否正常
- 數據表結構是否完整

### 佣金計算測試 (commission)

**執行時機**: 每次測試
**測試內容**:
- 各等級佣金計算正確性
- 首次推薦獎勵邏輯
- 佣金偏好切換

### 訂房生命週期測試 (lifecycle)

**執行時機**: 每次測試
**測試內容**:
- 創建訂房 → 確認入住 → 佣金計算
- 狀態轉換正確性
- 大使數據同步更新

### 取消與回滾測試 (cancellation)

**執行時機**: 每次測試
**測試內容**:
- 訂房取消後數據回滾
- 佣金撤銷正確性
- 複雜取消場景

### 點數操作測試 (points)

**執行時機**: 每次測試
**測試內容**:
- 使用住宿金抵扣
- 點數轉現金（2:1）
- 點數餘額正確性

### 結算管理測試 (payout)

**執行時機**: 建議執行
**測試內容**:
- 創建結算記錄
- 取消結算
- 結算審計追蹤

### 等級升級測試 (level)

**執行時機**: 按需執行
**測試內容**:
- LV1 → LV2 升級邏輯
- LV2 → LV3 升級邏輯
- 升級後佣金率變化

### 數據一致性測試 (consistency)

**執行時機**: 每次測試
**測試內容**:
- 點數餘額與 Payouts 記錄一致性
- 大使統計數據準確性
- 跨表數據關聯正確性

## 🛠️ 修改和新增測試

### 修改現有測試

1. 找到對應的測試套件文件：`test/suites/[category]-tests.js`
2. 編輯測試的 `execute` 函數
3. 保存後重新載入測試頁面

範例：修改佣金計算測試
```javascript
// 文件：test/suites/commission-tests.js

const lv1CommissionTest = {
    name: 'LV1 住宿金佣金計算',
    execute: async (framework) => {
        // 修改這裡的測試邏輯
        const expectedCommission = 1000;  // 修改預期佣金

        // ... 其他邏輯
    }
};
```

### 新增測試

1. 確定測試屬於哪個類別
2. 在對應的 `test/suites/[category]-tests.js` 中新增測試物件
3. 將新測試加入導出陣列

範例：新增新功能測試
```javascript
// 在 test/suites/commission-tests.js 末尾

const myNewTest = {
    name: '我的新功能測試',
    description: '測試某個新功能',
    category: 'commission',
    execute: async (framework) => {
        // 步驟 1: 準備數據
        const data = await framework.fetchSheetData();

        // 步驟 2: 執行操作
        await framework.apiCall('some_action', {
            partner_code: 'TEST_AUTO',
            // ... 參數
        });

        // 步驟 3: 等待數據同步
        await framework.wait(2000);

        // 步驟 4: 驗證結果
        const newData = await framework.fetchSheetData();
        if (newData.someValue !== expectedValue) {
            throw new Error(`驗證失敗: 預期 ${expectedValue}, 實際 ${newData.someValue}`);
        }

        return { success: true };
    }
};

// 加入導出陣列
const commissionTests = [
    // ... 現有測試
    myNewTest  // 新增這行
];
```

### 創建新測試類別

如果需要新的測試類別：

1. 創建新文件：`test/suites/[new-category]-tests.js`
2. 參考 `basic-tests.js` 的結構編寫
3. 在 `TEST-SUITE.html` 中添加新類別選項

## 📊 解讀測試結果

### 測試狀態

| 狀態 | 說明 |
|------|------|
| ✓ 通過 | 測試成功完成，所有驗證通過 |
| ✗ 失敗 | 測試執行失敗或驗證不通過 |
| ⚠️ 跳過 | 測試被跳過（如找不到測試數據） |

### 常見失敗原因

#### 1. 找不到測試大使

**錯誤訊息**: `找不到測試大使: TEST_AUTO`

**原因**: 測試大使未創建或代碼不匹配

**解決方案**:
- 確認測試大使代碼輸入正確
- 測試會自動創建大使，等待創建完成
- 檢查 Google Sheets Partners 表是否有該大使

#### 2. 佣金計算錯誤

**錯誤訊息**: `佣金計算錯誤: 預期 1000, 實際 1500`

**原因**:
- 首次推薦獎勵被錯誤觸發
- 測試大使已有推薦記錄

**解決方案**:
- 使用全新的測試大使代碼
- 勾選「測試後清理數據」
- 手動清除測試大使的推薦記錄

#### 3. 點數不一致

**錯誤訊息**: `發現 X 個點數不一致`

**原因**:
- Payouts 審計記錄與實際點數不匹配
- 某些操作沒有創建 Payout 記錄

**解決方案**:
- 檢查後端 API 是否正確創建 Payout 記錄
- 運行數據一致性測試查看詳細差異
- 檢查 COMMISSION-SYSTEM-ARCHITECTURE.md 確認邏輯

#### 4. API 超時

**錯誤訊息**: `API 請求超時`

**原因**:
- Google Apps Script 響應慢
- 網絡問題
- 並發請求過多

**解決方案**:
- 等待後重試
- 檢查網絡連接
- 減少同時執行的測試數量

## 🧹 測試數據清理

### 自動清理

勾選「測試後清理數據」選項，測試完成後會自動：

- 刪除所有 `guest_name` 包含 `TEST_` 的訂房
- 刪除相關的 Payout 記錄
- 重置測試大使數據（可選）

### 手動清理

如果需要手動清理：

1. 打開 Google Sheets
2. 在 Bookings 表中篩選 `guest_name` 包含 `TEST_`
3. 刪除這些訂房
4. 在 Payouts 表中查找相關記錄並刪除
5. 在 Partners 表中重置測試大使數據

## ⚠️ 注意事項

### 測試環境

- ⚠️ 測試會連接到**生產環境**的 Google Apps Script
- ⚠️ 測試會創建和修改**真實數據**
- ✓ 所有測試數據都使用 `TEST_` 前綴以便識別
- ✓ 建議勾選「測試後清理數據」避免污染生產數據

### 測試頻率建議

- **每次修改代碼後**: 運行基礎 + 相關類別測試
- **每週**: 運行完整測試套件
- **發布前**: 必須運行所有測試並全部通過

### 測試順序

測試會按以下順序執行（如果選擇）：

1. 基礎功能測試
2. 佣金計算測試
3. 訂房生命週期測試
4. 取消與回滾測試
5. 點數操作測試
6. 結算管理測試
7. 等級升級測試
8. 數據一致性測試

## 💡 最佳實踐

### 測試前

1. 確認 Apps Script URL 正確
2. 確認有權限訪問 Google Sheets
3. 使用專用的測試大使代碼
4. 勾選「測試後清理數據」

### 測試中

1. 不要關閉測試頁面
2. 不要同時手動修改 Google Sheets
3. 觀察日誌輸出了解測試進度
4. 記錄失敗的測試詳情

### 測試後

1. 檢查失敗的測試原因
2. 導出測試報告備份
3. 如有失敗，修復後重新測試
4. 更新相關文檔

## 🆘 常見問題

**Q: 測試要跑多久？**
A: 完整測試套件約 6-9 分鐘，可以只選擇需要的類別。

**Q: 測試失敗會影響生產數據嗎？**
A: 測試使用 `TEST_` 前綴，且會自動清理，不會影響正常業務數據。

**Q: 如何只測試修改的功能？**
A: 取消勾選其他類別，只選擇相關的測試類別執行。

**Q: 測試報告存在哪裡？**
A: 點擊「匯出報告」下載 JSON 文件，可保存到 `test/reports/` 目錄。

**Q: 發現系統有 bug 怎麼辦？**
A: 1) 記錄測試報告 2) 查看 CLAUDE.md 確認預期行為 3) 修復代碼 4) 新增對應測試防止回歸
